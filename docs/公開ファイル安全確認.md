# 公開ファイルとデプロイの安全確認

このリポジトリは Cloudflare Pages の公開用ファイルと、運用資料を同じルートに保持しています。
現状は `_routes.json` と `functions/_middleware.js` によって
`docs/` などへのアクセスを 404 にしています。

## 現在の対策の限界

- リポジトリに存在することと、公開URLから取得できることは別です。
- ソースコードの静的テストだけでは、Cloudflare上の実際の遮断状態は保証できません。
- Pagesのビルド出力ディレクトリを確認せずに、`docs/` を移動・削除しないでください。
- 404応答でも、過去の公開物がキャッシュに残っている可能性は別途確認が必要です。

## 公開前の確認手順

1. Cloudflare Pagesの **Build output directory** とデプロイブランチを確認する。
2. `/docs/計測の見かた.md`、`/docs/計測を見る.sh`、`/.gitignore` に外部からアクセスし、本文が返らず404になることを確認する。
3. `/service-materials/`、`/addHearingSheet_v3.gs` など、`_routes.json` に列挙された旧パスも確認する。
4. 正常な `/`、`/lp`、`/game`、`/love-game`、`/rhythm-game` が200で閲覧できることを確認する。
5. `/go/` リダイレクトと `/api/` の既存挙動を確認する。
6. 不正な公開が見つかった場合は、資料の機密性を評価し、必要に応じてキャッシュ無効化・情報の失効処理を検討する。

## 推奨する次の改善（未実施）

Cloudflare Pagesの出力を専用ディレクトリ（例: `dist/`）へ分離し、
HTML、CSS、JS、画像、必要なCloudflare設定のみをそこへコピーするビルド方式を検討する。
`docs/` や運用スクリプトを最初から出力に含めない方式が望ましい。

ただし、Cloudflare Functionsの配置、`_routes.json`、`_headers`、
既存のPretty URLとデプロイ設定を確認してから移行すること。
本資料は移行の提案であり、デプロイ設定を変更するものではありません。
